# CNplus 阶段 4 方案：第二个后端（VM vs JS 转译 vs 双做）

> 状态：**草案，待用户拍板**。本文只出方案不动代码。
> 日期：2026-08-25

## 背景与前提

- 语言功能已闭环：类（D-036）、切片（D-037）落地，核心特性齐
- 两后端（树遍历 + Python 转译）全量 495 测试逐字对拍
- 黄金语料 19 组——铁律 5 的保险已在手
- 阶段 3 还剩：LSP 补全/悬停/跳转、REPL（体验优化，非功能）
- 总纲的判断：**多后端才是真尾巴**——AST 边界干净时，加目标语言是「加文件不是改架构」

## 三条路线

### 路线 A：Python 字节码 VM（clox 风格，Python 实现）

AST → 自有字节码 → 栈式虚拟机解释执行。

```
.cnp → lexer → parser → AST → 编译器 → 字节码 → VM 执行
                                    ↑ 新增这两块
```

**得到什么**：
- 语义 100% 自己说了算（不再依赖 Python 解释器的任何行为）
- 架构验证的最强形式：证明前端真的与后端无关
- 为阶段 5+ 的本机可执行文件（Rust/Go 编译目标）铺路
- 教学叙事：「一门语言的完整实现」从词法到字节码全部可见

**付出什么**：
- 字节码设计 + 编译器（AST→字节码）+ VM 循环 + 帧栈，约 800–1500 行
- 36 个内置函数要在 VM 里重新接一遍
- `导入 "Python库"` **在 VM 里没有答案**——需要 FFI 桥（复杂）或明确降级（VM 模式不支持的导入报错说清）
- 类、异常、闭包都要在字节码层重新设计（异常 = 可跳转的信号、闭包 = upvalue）
- 工期：2–3 周

**风险**：异常和闭包的字节码实现是《Crafting Interpreters》公认的两处硬骨头；Python 实现的 VM 比 Python 本身慢——纯架构练习，性能上是负收益。

### 路线 B：JS 转译后端（与 Python 转译同构）

AST → JavaScript 源码，与 python_emit 完全同构：发射器 + 内联运行时。

```
.cnp → lexer → parser → AST → JS 发射器 → .js 文件（内联运行时）
                                    ↑ 新增这一块
```

**得到什么**：
- **浏览器直接跑 CNplus**：官网嵌在线运行器（Replit 式），教学场景杀手级
- 验证「加后端 = 加文件」的架构承诺，成本最低的验证方式
- JS 生态的库（虽然 `导入` 语义要重新定义——映射到 npm 包还是不做）
- 工期：**3–5 天**（发射器骨架照抄 python_emit，运行时语义照抄运行时源码.py）

**付出什么**：
- CNplus 的 JS 运行时要实现：严格真值、`/` 恒小数（JS 里 4/2=2 是整数！）、整数任意精度（JS Number 是 64 位浮点，`9007199254740993` 会失真——要么 BigInt 要么声明限制）、中文标识符合法性（ES 规范允许，✓）
- `导入` 同样是坑：浏览器里没有 pip。教学场景恰恰用不到导入，可先不支持
- 性能：现代 JS 引擎很快，比树遍历 Python 快一个量级

**风险**：JS 的 Number 语义陷阱（整数精度、`-0`、`NaN`）需要运行时防御；好在黄金语料就是对拍利器，两后端行为不一致会被当场抓住。

### 路线 C：先 B 后 A（JS 先行，VM 随后）

教学价值立刻兑现（官网在线运行器），架构验证也完成（第二后端落地）；
VM 作为阶段 5 的独立项目慢慢做，不抢现在的节奏。

## 对比总表

| | A：VM | B：JS 转译 | C：B 先 A 后 |
|---|---|---|---|
| 工期 | 2–3 周 | 3–5 天 | 先 3–5 天 |
| 教学价值 | 低（用户看不见） | **高**（在线运行器） | 先高 |
| 架构验证 | **最强** | 强 | 强 |
| `导入` 库 | 需 FFI 或放弃 | 先不支持 | 同 B |
| 性能 | 负收益（比 Python 慢） | 提升 10–100× | — |
| 语义主权 | **100%** | 95%（JS 语义防御） | — |
| 长期价值 | 本机可执行铺路 | 生态铺路 | 两者都有 |

## 推荐：路线 C

**理由**：
1. **用户能看见的东西优先**——CNplus 的核心卖点是给中文用户的低门槛，
   官网「打开就能跑」比任何架构美学都直接命中卖点
2. **成本排序即验证顺序**——JS 转译 3 天完成架构承诺的验证，VM 2–3 周
   才能验证同样的东西；先用便宜的验证，再决定贵的值不值
3. **VM 的真正动机（性能、本机可执行）在 2026 年都不成立**：玩具期
   没有性能需求，Rust 编译目标在语言稳定前做了也是重写
4. **风险隔离**——JS 路线如果碰壁（Number 精度等），损失的只是 3 天；
   VM 路线碰壁（异常+闭包字节码），损失的是 3 周

**JS 转译的执行草案**（拍板后展开成任务清单）：
- `cnplus/backends/js_emit/发射器.js`？不——`发射器.py`（Python 写，
  生成 JS），照抄 python_emit 的骨架：每语句一行、运行时全函数调用
- `运行时源码.js`：移植运行时源码.py 的全部函数（加/条件/取成员/
  严格真值/…），整数用「安全整数检查 + 报错」策略而非 BigInt
  （教学场景超 2^53 的整数是异常路径不是正常路径）
- 黄金语料全部跑三后端对拍（树遍历 vs Python 转译 vs JS 转译）
- CLI：`cnp 运行 --js x.cnp`（本机 node 执行）
- 官网在线运行器：embedded runner（阶段 4.5，独立小项目）
- `导入` 在 JS 后端 v1 明确不支持，报错信息说清「JS 运行环境暂不支持导入」

## 附加议题：在线运行器（网页）—— 2026-08-25 用户提议后的范围界定

用户提议「在线 IDE / 终端 IDE」。按 D-006（不自研 IDE）界定范围：

**做**：单文件**在线运行器**（playground）——
- 一个网页：代码框（带语法高亮）+ 运行按钮 + 输出面板
- 高亮从 `keywords.toml` 生成 Monarch 语法定义（数据驱动，同铁律 4）
- 执行走 JS 后端的内联运行时，**纯静态站，零后端服务**
- 这是 JS 后端的自然展示面，工期 1–2 天（JS 后端完成后）
- 「在线 IDE」90% 的教学价值，5% 的成本

**不做**（D-006 的边界）：
- 多文件 / 文件树 / 标签页
- 浏览器内补全、悬停、跳转（需要 LSP-over-WebSocket 桥 = 真后端服务，
  且重造 VSCode 扩展已有的能力）
- 调试器

**终端侧的对应物**：`cnp 交互` REPL（阶段 3 已列的剩余项）——
「终端 IDE」的正确尺寸就是交互式解释器，不是 TUI 编辑器。

## 不做的事

- **不做 Rust/Go 本机编译**（阶段 5+，语言稳定后再议）
- **不做增量编译**（YAGNI，D-008）
- **不把 VM 扔掉**：总纲里它是合法的阶段 5 目标，本文档只是把它的
  优先级排在 JS 之后
