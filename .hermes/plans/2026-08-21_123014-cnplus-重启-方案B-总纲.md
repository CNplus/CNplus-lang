## 一、目标

做一门**中文编程语言**，玩具起步，但架构上留有升级成正式语言的出口。

**一句话架构**：自有 lexer + parser + AST，后端可插拔；首发后端把 AST 转译成 Python 源码，将来可换成字节码 VM 或别的目标语言，**前端一行不改**。

**核心判断**：玩具和正式语言的分界不在功能（GC、类型系统、VM），而在「源码 → AST」和「AST → 执行」之间有没有一条干净的接缝。有缝，换后端是一个周末；没缝，任何升级都是重写。

**这次要修正的历史错误**：
- `CNplus-python` 只有一层中文函数名封装，没有自己的表示 → 无法演进
- `CNplus-mixed` 用 `string::find` 子串匹配派发，连 token 都没有 → 只能从零重来

两次都是字符直接跳到执行，中间层不存在。**这次先把中间层建起来。**

## 二、不可回填的五条铁律（第一天必须做对）

这五条现在做几乎不花钱，事后补要重写前端。任何任务与之冲突，以本节为准。

### 铁律 1：自有 AST 节点
不用 Python 的 `ast` 模块，不用裸 dict。节点是 **CNplus 的语义单位**，不是宿主的。
> 反例（假方案 B）：节点叫 `IfNode` 但字段结构照抄 Python 的 `ast.If`。那只是换个写法的关键字替换，缝仍然不存在。

### 铁律 2：万物带 Span
**每个 token、每个 AST 节点**都带 `Span`（起止行、列、字节偏移）。
这是最多人跳过、也最不可能回填的一条。错误信息、source map、调试器、LSP 全建在 span 上；事后加 span 等于把整个前端重写一遍。

### 铁律 3：后端接口先于第二个后端存在
第一天就定义 `Backend` 抽象基类，哪怕只有一个实现。有它，第二个后端才是「加文件」而不是「改架构」。

### 铁律 4：关键字表是数据
一张 `cnplus/lexer/keywords.toml`，不硬编码字符串。免费换来：简繁两套、方言别名、英文回退，且语法高亮 / LSP 读同一张表。

### 铁律 5：黄金测试语料
`tests/golden/` 下每个用例一个目录（源文件 + 期望输出），一键全跑。
**这是将来敢重写后端的唯一保险。** 没有它，写完 VM 你不知道行为变了没有。

## 三、最大陷阱：语义泄漏（必须主动防御）

转译到 Python 会让 CNplus **悄悄继承 Python 的语义**：整除行为、真值判断、数值精度、作用域规则、求值顺序。

危险在于：黄金语料记录的会是「Python 恰好这么干」，而不是「CNplus 规定这么干」。等阶段 4 换成自有 VM，一大批程序会以说不清原因的方式坏掉。

**对策（成本很低，必须做）**：
1. 先写 `docs/spec/00-语义约定.md`（两页，见下）
2. 测试断言**规定的行为**，不是观察到的宿主行为
3. 凡「Python 这样所以这样」的地方，显式标记为**未定义行为**，不让用户依赖

这一步区分「一门语言」和「一张 Python 的面具」。

## 四、语义约定（阶段 0 前先定稿）

写进 `docs/spec/00-语义约定.md`。以下是提案，实现前需确认。

| 主题 | 规定 | 与 Python 的差异 |
|---|---|---|
| **整数** | 任意精度 | 同 |
| **除法** | `/` 恒为浮点；`//` 向下取整 | 同（但要写下来，不能靠继承） |
| **真值** | **只有 `真`/`假` 能出现在条件位置**。`如果 0` → 编译错误 | **不同**。Python 的隐式真值是初学者头号坑源 |
| **相等** | `1 == 1.0` 为真；跨类型（数 vs 串）比较 → 错误，不是 `假` | **不同** |
| **作用域** | 函数体是新作用域；赋值即声明本地；改外层需 `外部` 关键字 | 近似，但显式化 |
| **求值顺序** | 严格从左到右，包括函数实参 | 同 |
| **未初始化** | 读未声明变量 → 编译期错误（不是运行时 NameError） | **不同**，更早报错 |
| **字符串** | 不可变，Unicode 码点序列 | 同 |
| **错误** | 所有运行时错误携带 span + 稳定诊断码 | 不同（Python 只有 traceback） |

> 「真值」和「跨类型相等」这两条是**故意和 Python 不一样**的——它们既服务初学者（早报错、报得准），又证明前端确实是自己的，而不是 Python 的皮。

### 阶段 0 详细任务（TDD，每个 2–5 分钟，共 16 个）

> 顺序不可打乱：Span → 诊断 → 关键字 → 归一化 → lexer → AST → parser → 后端接口 → 求值器 → CLI → 语料

- **0.1** `git init` + `pyproject.toml` + `uv python pin 3.11` + 首次提交
- **0.2** `source.py`：`Position(行,列,偏移)` / `Span(起,止)` / `SourceFile`。测试：span 合并、切片取原文
- **0.3** `diagnostics.py`：`Diagnostic(码, 消息, span, 提示)` + `DiagnosticBag`。渲染器输出源码摘录 + `~~~` 波浪线。测试：单行 / 跨行 / 中文宽字符对齐（**宽字符对齐是坑，务必测**）
- **0.4** `keywords.toml` + 加载器。含简繁双写、英文回退。测试：`如果`/`若`/`if` 映射到同一 `TokenKind.IF`
- **0.5** `normalize.py`：`，（）：""` → `,():""`。**只在 lexer 入口做一次**，绝不渗到 parser。测试：混合全半角源文件
- **0.6** lexer：数字、字符串、标识符（含中文）、标点、注释。每个 token 带 span
- **0.7** lexer 错误路径：未闭合字符串、非法字符 → 诊断而非崩溃
- **0.8** `ast.py`：节点定义（`字面量` `变量` `二元` `一元` `调用` `令` `赋值` `如果` `循环` `函数` `返回` `表达式语句`）。全部 `@dataclass(frozen=True)` 且带 `span`
- **0.9** Pratt 表达式解析：字面量、一元、二元（优先级表）、括号、函数调用
- **0.10** 语句解析：`令 x = 1`、赋值、`如果/否则`、`循环`、`函数`、`返回`
- **0.11** **parser 错误恢复**（为编辑器而生，见 D-005）：AST 加 `错误节点`；恐慌模式跳到同步点（行首/换行/关键字）继续；parser **恒返回 `(AST, 诊断列表)`，永不抛异常**。测试：残缺输入（`令 x =` / `如果` 后无体）仍产出可用 AST 且报告诊断

- **0.14** `builtins.py`：`打印` / `判断` / `随机数`（沿用 2021 年那三个函数的签名，算是接上）
- **0.15** `cli.py`：`cnp 运行 x.cnp`、`cnp 词法 x.cnp`、`cnp 语法树 x.cnp`（后两个是调试出口，等于把 2022 年的「下标查找器」做正规）


## 类/对象方案存档（2026-08-23 讨论，2026-08-24 定稿）

> 2026-08-23 用户精力不足先存档；2026-08-24 经四轮讨论定稿如下。

**已拍板（D-036）：方案 C —— 类，无继承。**

| 项 | 定名 | 备注 |
|---|---|---|
| 声明类 | `类` | 接受单字（生活用字：分类/同类），例外于第 6 条 |
| 构造方法 | `初始化` | **括号参数自动成为字段**（免 `自己.x = x` 样板）；块体只写校验/派生逻辑，可省略 |
| 指代自身 | `自己` | **隐式关键字**，方法签名不写形参；指代只看定义处（方法所属实例） |
| 造实例 | `学生("小明", 18)` | 与函数调用同形 |
| 继承 | **不做** | 组合优于继承；将来加 `是一种` 是纯增量 |

定稿样例：
```
类 学生
    初始化(名字, 年龄)
        如果 年龄 < 0
            抛出 "年龄不能是负数"
    函数 自我介绍()
        打印(@"我叫{自己.名字}，今年{自己.年龄}岁")
    函数 过生日()
        自己.年龄 = 自己.年龄 + 1

设 小明 = 学生("小明", 18)
小明.自我介绍()
```

讨论中否决的候选（留档）：`新建时`（时间状语站方法位，需解释）；方法名指代自身
（`自我介绍.名字`，撞名/指代漂移/嵌套失效）；显式可改名 self（参数数不对上，
零基础经典坑）。设计理由：隐式 `自己` + 类头参数自动成字段（Kotlin 主构造方向）。

实现范围：AST 加 `类声明` 节点；`初始化` 括号参数自动转存字段；转译后端生成
真 Python class（白捡 MRO 无用武之地，但属性查找快）；树遍历后端用
类值(方法表)+实例值(字段表+类指针)。工作拆解：AST → parser → checker →
树遍历 → 转译 → 对拍 → 综合示例（类重写通讯录）→ 发版 v0.9.0。

### 三个方案

**方案 A：经典类（先定义模板，再造实例）**
```
类 学生
    新建时(名字, 年龄)
        自己.名字 = 名字
        自己.年龄 = 年龄
    函数 自我介绍()
        打印(@"我叫{自己.名字}，今年{自己.年龄}岁")

设 小明 = 学生("小明", 18)
小明.自我介绍()
```
继承用中文本来的说法（亮点）：
```
类 狗 是一种 动物
    函数 叫()
        打印("汪汪")
```
`是一种` 是中文母语者的自然说法（"狗是一种动物"），比 `继承`/`extends`
都自然，过得了命名第一条。

**方案 B：不做类，把现有写法扶正**
给字典加语法糖让"数据+行为"绑一起，不引入类/实例/继承：
```
函数 造学生(名字, 年龄)
    设 我 = {"名字": 名字, "年龄": 年龄}
    我.介绍 = 函数()
        打印(@"我叫{我['名字']}")
    返回 我
```
零新概念，但每次手写样板，无类型概念——十个学生十份重复函数定义。

**方案 C：先做无继承的类**（A 的子集）
类、字段、方法、`自己` 都有，**但不做继承**。等有真实需求再加。

### 权衡表

| | A 完整类 | B 不做类 | C 类但无继承 |
|---|---|---|---|
| 新概念数量 | 多（类/实例/方法/自己/继承/父类调用） | 0 | 中（无继承/父类调用） |
| 对零基础门槛 | 高 | 低 | 中 |
| 对有基础的人 | 符合预期 | 觉得"没做完" | 基本够用 |
| 实现工作量 | 大（父类方法解析最麻烦） | 小 | 中 |
| 以后能否扩展 | — | 加类是破坏性的 | 加继承是纯增量 |

### 我（助手）的推荐：C

继承恰是 OOP 里最易误用、最难教的部分，零基础十有八九用不到，有基础少了
它也能干活（应鼓励组合优于继承）。C→A 是纯增量，以后想加不用推翻已有写法。
B 的问题是把成本转移给每个用户（写十个类抄十遍样板）。

### 待用户拍板的命名（会出现在用户天天写的代码里）

| 用途 | 候选 | 助手倾向 |
|---|---|---|
| 声明类 | `类` / `种类` / `模板` | `类`（通行认知，但**单字+术语，撞命名第 6 条**，待议） |
| 构造函数 | `新建时` / `创建时` / `初始化` | `新建时`（"新建一个学生时要做什么"） |
| 指代自身 | `自己` / `本身` / `我` | `自己`（双字自然） |
| 造实例 | `学生(...)` / `新建 学生(...)` | `学生(...)`（第 5 条能不写就不写） |
| 继承 | `是一种` / `继承` | `是一种` |

**最大悬而未决点**：`类` 是单字又是术语，撞第 6 条（用户为 `问`→`询问`
定的原则）。`种类`/`类型`/`模板` 各有毛病，暂无更好双字词——需用户定夺
"我要定义一种叫学生的东西"该怎么说。

## 九、如何续写本计划

1. **阶段展开**：动工某阶段前，把「提要」拆成 0.1 那样的 2–5 分钟任务列表，追加到本文件对应小节。
2. **决策**：任何架构变更先在决策日志追加一行，重大的另写 `docs/decisions/NNNN-*.md`。
   **追加时按编号插到末尾**，不要插在开头——曾因此让日志顺序错乱到需要重排。
3. **铁律不可协商**：第二节五条与任何后续任务冲突时，以铁律为准；确需违反必须写 ADR 说明。
4. **语料只增不删**：修 bug 时先加语料复现，再修。语料是资产。
5. **每阶段末回填**：更新进度看板 + 记录实际行数/耗时，用于校准后续估算。
6. **被推翻的决策不删除**：在原条目末尾加 `⚠️ 已由 D-0NN 修正`，保留推理轨迹。
   已有三条：D-016（遍历语序）、D-025（输入函数名）、D-026（插值串前缀）。

### 操作教训（真实踩过，勿重犯）

| 教训 | 事故 |
|---|---|
| **不要用脚本批量字符串替换改代码** | 曾把两个示例文件**写空**；曾把 `_问`→`_询问` 叠成 `_询询问`，139 个测试瞬间变红 |
| 若必须批量，替换后立刻 grep 查畸形（重复词根）+ 跑全量测试 | 同上 |
| 改动前先取**改前的真实输出**当基准，改后逐字比对 | v0.8.0 改 50 处用法时用 `git stash` 取基准，确认三个确定性示例输出完全一致 |
| 含随机数的程序不能做输出比对 | 曾把「两后端输出一致」测试加到含 `随机数` 的示例上，必然失败——正确做法是跳过并说明原因，而非弱化断言 |
| 报告成功前必须**回读核实**，不能只看退出码 | 曾误报「计划已更新」而实际未写入；此后一律读回确认 |
| CHANGELOG 历史条目不跟着改名 | 那是当时的事实记录 |
| 写完长 md 用 Python 扫 `\ufffd` | API 中转切换曾导致单字符损坏 |

### 「写真实程序」是最有效的 debug 手段

三次验证过：为展示语言全貌而写的综合示例，每次都当场暴露单元测试碰不到的 bug。

- `15-待办清单` → 暴露 `问数字` 在 EOF 时**死循环**（真实卡死，Ctrl+D 即触发）
- `17-通讯录` → 暴露**索引复合赋值**未实现（`字典[键] += 1` 解析报错）、
  以及**遮蔽内置名时两后端行为分叉**（同一段代码一边报错一边正常）

**结论：每次加完一批特性，写一个用上全部特性的真实程序，比补单元测试更能发现问题。**
